Nginx 配置与 Web 架构入门

Nginx 是常见的 Web 流量入口：既能直接返回静态文件，也能把 API 转发给后端。本文分三部分：nginx.conf 怎么写、用 curl/wget 看页面源码、以及浏览器 / 前端 / Nginx / 后端 / 数据库各自扮演什么角色。

一、nginx.conf 配置结构

1.1 核心结构：6 个配置块

nginx.conf 由嵌套的 block（上下文）组成，从外到内依次为：

层级 块名 作用
1 main（全局，无花括号） 进程管理、日志、PID 等全局参数
2 events {} 网络事件模型、并发连接数
3 http {} HTTP 服务全局配置（所有 server 共享）
4 upstream {} 定义后端服务器池（负载均衡）
5 server {} 虚拟主机（一个端口/域名对应一个）
6 location {} URL 路由匹配规则（最细粒度）

继承规则：外层块的指令自动被子块继承，子块可覆盖同名指令。

1.3 location 匹配优先级

注意：不是从上到下按顺序匹配！

前缀 示例 优先级 说明
= 精确匹配 location = /favicon.ico 1（最高） 完全匹配，命中后立即返回
^~ 前缀匹配 location ^~ /static/ 2 匹配后不再走正则
~ / ~* 正则 location ~* \.php$ 3 区分/不区分大小写
普通前缀 location /api/ 4（最低） 最长前缀匹配

规则：先找普通前缀里最长的，记住它；再看正则，正则命中就用正则；正则都不中，就用记住的那个前缀。

三、前端 / 后端 / Nginx / 浏览器的关系

3.1 外卖类比

角色 类比 干什么
浏览器 顾客 发起需求，最终看到结果
Nginx 餐厅前台/服务员 接单、分发——静态的自己给，需要后厨做的转给后厨
前端 餐厅菜单、装修 用户看到的一切界面（HTML/CSS/JS），是静态文件
后端 后厨 接到订单后真正干活——查库存（数据库）、算账、把结果做出来
数据库 仓库/冰箱 存原料（数据），后厨来取

3.2 各角色详解

浏览器（用户侧）

  • 跑在用户的电脑/手机上
  • 发请求：用户输入 URL 或点击按钮，浏览器向服务器发出 HTTP 请求
  • 渲染页面：拿到 HTML/CSS/JS 后，解析、执行、绘制成网页
  • 浏览器只跟 Nginx 对话，不直接连后端，也不直接碰数据库

Nginx（中间人 / 流量入口）

  • 跑在服务器上，监听 80/443 端口，是所有请求的第一站
  • 干三件事：
  • 为什么需要 Nginx 当中间人：
    • 安全：后端不暴露在公网，只有 Nginx 对外开放
    • 性能：静态文件 Nginx 自己就能秒回
    • 负载均衡：多个后端实例时，Nginx 分发请求
    • 统一入口：前端和后端共用同一域名和端口，避免跨域

前端（用户看到的一切）

  • 一堆静态文件（打包后的 HTML/CSS/JS），放在 Nginx 的 root 目录下：
  • 浏览器加载后，JS 在浏览器里运行，发起 AJAX/Fetch 请求调后端 API
  • 关键点：前端代码跑在用户的浏览器里，不在服务器上跑

后端（干活的）

  • 真正处理业务逻辑的程序（Node.js / Java / Python / Go 等）
  • 监听内部端口（如 127.0.0.1:8080），只接受 Nginx 转发过来的请求
  • 做的事：接收 API 请求 → 查数据库、执行业务逻辑 → 返回 JSON 数据
  • 关键点：后端代码跑在服务器上，用户永远看不到后端代码

数据库（存数据）

  • MySQL / PostgreSQL / Redis 等
  • 后端直接连数据库读写
  • Nginx 和浏览器都不碰数据库

3.4 有无 Nginx 的对比

问题 没有 Nginx 有 Nginx
静态文件 后端自己返回（慢） Nginx 直接秒回
后端暴露 后端直接对公网开放（危险） 后端藏在内网
跨域问题 前端 3000 端口调后端 8080 端口 → CORS 麻烦 同域名，Nginx 分发，无跨域
多实例 没法负载均衡 Nginx upstream 分发
HTTPS 每个后端都要配证书 Nginx 统一配 SSL

3.5 一句话总结

浏览器是顾客，Nginx 是前台，前端是菜单和装修，后端是后厨，数据库是仓库。
顾客只跟前台打交道，前台决定是自己给（静态文件）还是转给后厨（API），后厨需要的时候去仓库取料。
